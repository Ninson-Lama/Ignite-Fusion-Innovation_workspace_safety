## Entry procedure

Add a row only when a genuine source can be retained or referenced. A suitable entry should:

1. use the actual interaction date and channel;
2. paraphrase feedback accurately and distinguish it from the team’s interpretation;
3. identify a concrete requested change, or state that no change was requested;
4. record the team decision and reason;
5. link the resulting requirement, issue, commit, screenshot or test where available;
6. preserve the evidence location without copying personal information unnecessarily; and
7. use an honest status such as `Raised`, `Accepted`, `Implemented`, `Verified by client` or `Declined with rationale`.

Do not mark an item `Verified by client` merely because it was implemented. Client confirmation requires its own genuine evidence.
