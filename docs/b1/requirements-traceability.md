## Status legend

- **Implemented; browser/hosted verification pending** — a local implementation is present and may have local check coverage, but its user journey or configured-service behaviour remains unverified.
- **Configured; partial hosted verification recorded** — the target service is configured and named hosted/browser observations passed, but the full linked test matrix remains incomplete.
- **Implemented; local partial checks recorded** — named local unit or embedded-database paths passed, but that does not satisfy the complete linked case or hosted/browser evidence requirement.
- **Planned** — accepted scope without completed implementation evidence.
- **Verified** — may be used only after a dated test result and genuine evidence location are added.

## Evidence completion procedure

1. Configure a real Supabase project, apply migrations and seed data, and create separate trainee, manager and administrator test accounts without committed passwords.
2. Execute the linked test IDs in `testing-plan.md` and record actual results verbatim.
3. Capture only genuine screenshots using the identifiers in `ui-design.md`.
4. Replace a status with **Verified** only when the test result and evidence location support it.
5. Re-check this matrix whenever routes, policies, schema or completion rules change.
